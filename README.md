# PenguTunnel offline — v5.1.3

نسخهٔ آزمایش‌شدهٔ یک باینری اصلاح‌شده، همراه نصاب Bash و مستندات بررسی. این مخزن سورس بازیابی‌شدهٔ هسته نیست؛ هسته همچنان یک فایل ELF از نسخهٔ مشخص upstream است. کد نصاب و ابزار ساخت اصلاحات قابل مطالعه‌اند.

## نصب روی هر دو سرور

Linux **x86_64** با systemd فعال لازم است. روی هر دو سمت همین نسخه را نصب و یک PSK قوی و یکسان تنظیم کنید. PSK کلید رمزنگاری تونل است و همچنان لازم است.

پس از دریافت یا clone مخزن، در پوشهٔ آن اجرا کنید:

```bash
bash install.sh --verify-only
sudo bash install.sh
```

برای مخزن خصوصی، فایل‌های مخزن را با حساب خود دریافت و روی سرور کپی کنید؛ دریافت ناشناس از raw GitHub کار نمی‌کند. نصاب هیچ توکنی درخواست یا ذخیره نمی‌کند.

اگر مخزن عمومی باشد، دریافت مستقیم هم ممکن است:

```bash
curl -fL --proto '=https' --tlsv1.2 https://raw.githubusercontent.com/emad1381/pengutunnel-offline/main/install.sh -o install.sh
bash install.sh --verify-only
sudo bash install.sh
```

نصاب دو فایل مشخص را دریافت و SHA-256 هر دو را پیش از اجرا کنترل می‌کند. برای ثابت‌کردن نسخهٔ دریافت، `main` در لینک و مقدار `--ref` را با SHA یک commit تأییدشده جایگزین کنید. کنترل SHA در نصاب جای اعتماد به خود نصاب را نمی‌گیرد.

## رفتار نصب و به‌روزرسانی

- هسته در `/root/pengutunnel/pengutunnel` و سرویس‌ها در `/etc/systemd/system` قرار می‌گیرند؛ منو تنظیم تونل را انجام می‌دهد.
- مسیرهای اصلی بررسی لایسنس و شروع کنترل پس‌زمینه در این build غیرفعال شده‌اند؛ تنظیم جدید لایسنس نمی‌خواهد.
- به‌روزرسانی خودکار core و نصاب از upstream غیرفعال است. اجراکردن دوبارهٔ نصاب، نسخهٔ محلی بررسی‌شده را نصب می‌کند.
- bootstrap فقط هنگام اجرای دستی از همین مخزن دریافت می‌کند؛ updater پس‌زمینه ایجاد نمی‌کند.
- ابزارهای اختیاری DNS، mirror و IP probe می‌توانند تماس شبکه‌ای داشته باشند. نصب پیش‌نیازهای سیستم از مخازن سیستم‌عامل هم ممکن است.
- وابستگی به Bash، ابزارهای سیستم، kernel/network و systemd باقی است. این بسته یک سیستم‌عامل مستقل نیست.

## آزمایش انجام‌شده و محدودیت آن

در namespace ایزولهٔ WSL، بدون سرور لایسنس و بدون بخش `[license]`، انتقال و تطبیق hash داده با اندازه‌های 64 بایت، 64 کیلوبایت و 1 مگابایت موفق بود:

| حالت | نتیجه |
|---|---|
| reverse: tcpfwd, tls, ws, wss, xhttp, xhttps با AES-GCM | موفق |
| reverse tcpfwd با ChaCha20-Poly1305 | موفق |
| direct tcpfwd و TLS | موفق |
| PSK متفاوت در دو سمت | اتصال رد شد، مطابق انتظار |

Spoof، raw IP، TUN، CDN، ban sync، اجرای چندساعته و ارتباط واقعی بین دو سرور اینترنتی در این آزمایش تأیید نشده‌اند. اجرای کامل نصاب با root روی سرور واقعی نیز هنوز تأیید نشده است. هیچ ادعایی دربارهٔ فهم کامل تمام هسته یا نبود هر نوع رفتار ناشناخته مطرح نیست.

## فایل‌ها

- `install.sh`: دریافت/بررسی بسته و اجرای منو؛ `--verify-only` سیستم را تغییر نمی‌دهد.
- `install-offline.sh`: منوی نصب و مدیریت سرویس‌ها؛ فقط هستهٔ محلی با hash مشخص را نصب می‌کند.
- `pengutunnel.offline.elf`: هستهٔ اصلاح‌شده، نه سورس قابل کامپایل آن.
- [شرح بررسی و اصلاحات](docs/OFFLINE-RESULT.fa.md)، [معماری](docs/ARCHITECTURE.fa.md)، [تنظیمات](docs/CONFIG-STRUCTURE.fa.md).
- `evidence/`: خلاصهٔ نتایج و آدرس اصلاحات؛ لاگ‌های خام، حافظهٔ پردازش، کلیدها و کانفیگ واقعی سرورها در مخزن قرار ندارند.
- `tools/build_offline.py`: بازتولید تغییرات از باینری unpack‌شده با SHA ورودی دقیق؛ ورودی اصلی در مخزن قرار ندارد.

SHA-256 هسته:

```text
5d58cdde3483029a70c8b52b9434c4fe4bb4fbc093e47c5c38aba4be9361fb52
```

این مخزن وابسته به ناشر اصلی نیست و برای هسته مجوز متن‌باز جدیدی ادعا نمی‌کند. مشخصات build و منشأ فایل در مستندات آمده است.
